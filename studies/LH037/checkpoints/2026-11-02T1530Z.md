## New statements, measure 3

### Google (rule panel; first successful read, through the replaced route)

The feed (`Last-Modified` 28 October 2026 15:35 GMT) carries two bulletins naming the CVEs. Each bulletin's full text is in the feed, which is the route. The two pages they link were added to panel.json and fetched once: Apigee's security bulletins page and Google Cloud's blog post.

- **GCP-2026-070**, published 2026-10-21, severity Critical. Quoted: "While Google Cloud itself is not vulnerable, users of this language running on Google Cloud may be vulnerable." It also says: "All PHP versions between 5.4 and 8.5" affected; fixes in "PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35"; some workloads on App Engine Standard, Cloud Run and Cloud Run functions "may be automatically patched". It links the blog post below.
- **Blog post**, "Responding to core PHP vulnerabilities CVE-2026-109618 and CVE-2026-109619", by Chris Betz (CISO, Google Cloud) and Raluca Ada Popa (Google DeepMind). Published 2026-10-21T21:14:39Z (page metadata). An editor's note says it was updated on 21 and 22 October and on "Oct. 23, 2026 at 3:20 p.m. PDT".
  - It repeats "Google Cloud itself is not vulnerable".
  - **Serverless runtimes and branches:** App Engine standard environment "(PHP 8.2 and newer): Applications are updated automatically. No action is required." Cloud Run and Cloud Run functions (PHP 8.2 and newer) are updated where automatic base image updates are enabled. App Engine flexible is not updated automatically.
  - "Unsupported runtimes will not be patched ... Applications on PHP 5.5, PHP 7.2, PHP 7.3, PHP 7.4, or PHP 8.1 remain vulnerable and must be upgraded to PHP 8.2 or newer."
  - It says "Gemini 4 Argon made an invaluable contribution to finding the vulnerability, exploit development, attack detection, and validation of the patch", alongside Wiz Research.
  - Its only sentence near a statement of exploitation (quoted): "Mandiant Threat Defense is actively supporting customers by monitoring curated detections in Google Security Operations and hunting for evidence of intrusion activity related to this campaign." It names no campaign, no victim and no Google product, and says nothing was found.
- **GCP-2026-072** (Apigee), published 2026-10-24. Apigee's bulletins page says "Last updated 2026-10-26 UTC" and gives no update date for this bulletin. Severity Critical.
  - **Not affected:** "Apigee, Apigee Hybrid, Apigee Edge for Public Cloud, API hub, and the Apigee integrated portal don't use PHP and aren't affected." Apigee Edge for Private Cloud is not affected "apart from its optional Drupal developer portal". "The impact is limited to Drupal-based Apigee developer portals, which customers deploy and operate."
  - **Affected:** Apigee Developer Portal Kickstart from Google Cloud Marketplace; the Kickstart Docker image (`ghcr.io/apigee/docker-apigee-drupal-kickstart`); self-hosted Drupal 10 and 11 portals built with Kickstart or the Apigee Edge module; Apigee Edge for Private Cloud Drupal 7 and Drupal 9 portals (all versions); and self-hosted Apigee Edge for Public Cloud Drupal 7 portals.
  - **Fixes:**
    - Marketplace: "New deployments from Google Cloud Marketplace use a patched image with PHP 8.3.36". Images `apigee-devportal-drupal-202610231240` and later are patched; existing deployments must be patched by the customer.
    - Docker: the `:latest`, `:main` and `:nightly` tags "have been republished with PHP 8.3.36".
    - Self-hosted Drupal 10 and 11: update PHP to a fixed release.
    - Private Cloud Drupal 7 and 9 portals: "These portals run PHP 7.3 or 7.4 on RHEL/CentOS 7, RHEL 8, or Amazon Linux 2, where no packaged fix is available." The advice is to take the portal offline or restrict it, apply the interim mitigations, and migrate. The bulletin adds that upcoming `apigee-setup` releases for 4.53.01 and 4.54.00 will block installing the portal profile.
  - **Workarounds:** interim PHP settings (`session.upload_progress.enabled=0`, `memory_limit=-1`, a small `post_max_size`, and on PHP 8.5 `fatal_error_backtraces=0`), and blocking `multipart/form-data` where uploads are not needed.
  - **Exploitation:** no statement that any portal was exploited. It has a "Check for compromise" section, which is conditional: "Updating PHP doesn't remove an attacker who exploited the portal before it was patched."

**Google's class:** *affected, fixed for some*, from its most recent statement (GCP-2026-072). Patched images are named for the Kickstart Marketplace and Docker products, and no fix is available for the Private Cloud Drupal 7 and 9 portals. The products named are ones customers deploy and operate. Google's earlier bulletin and the blog say Google Cloud itself is not vulnerable.

**PHP branch (measure 4), newly stated:**
- Apigee Developer Portal Kickstart (Marketplace image and Docker image): PHP 8.3, at 8.3.36 after the fix. PHP's 21 October releases fix this branch.
- Apigee Edge for Private Cloud Drupal 7 and Drupal 9 portals: "PHP 7.3 or 7.4". PHP's 21 October releases fix neither branch, and the bulletin says no packaged fix is available.
- Google's serverless runtimes: PHP 8.2 and newer patched automatically where enabled. PHP 5.5, 7.2, 7.3, 7.4 and 8.1 runtimes "will not be patched".

**Clocks.** Vendor's clock: first published 21 October (GCP-2026-070 and the blog, 0 days after PHP's releases); Apigee's bulletin 24 October (3 days). First fixed release named: the patched Marketplace image `apigee-devportal-drupal-202610231240`, whose name carries 23 October 12:40 (2 days). That date comes from the image's name, not from a date the bulletin gives. Lighthouse's clock: first seen at this read.
