## crossref.org/blog/announcing-changes-to-rest-api-rate-limits/

Published 5 November 2025, Martyn Rittman and Luis Montilla (Crossref). "From 1 December 2025, we will be revising the rate limits for the public and polite pools of the REST API". Public pool: single-record requests 5 per second, concurrency 1; list requests 1 per second, concurrency 1. Reason: "we've seen periods of instability where we haven't been able to keep the API available for all users"; "a few send spikes of large numbers of requests in a short space of time, sometimes making it difficult for others to access the service." ## community.crossref.org/t/refining-rest-api-limits-for-improved-stability-and-reliability/16137

Posted 21 July 2026 by mrittman (Crossref). "From today, 21 July 2026, we will be implementing changes to REST API limits." "Requests that return lists of records are limited to 1 request per second for the public pool." "Requests for a single record remain unchanged at 5 requests per second for the public pool." Reason: "These changes are being made to maintain the stability of our system." Describes users who "make large volumes of complex requests using multiple IP addresses" and email-based limiting to stop users "using multiple IP addresses to bypass rate limits."
