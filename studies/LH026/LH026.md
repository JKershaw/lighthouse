# Drupal's published layers extend the fixed PHP base layers

**Study:** LH026, version 0.1, 22 October 2026. **Writer:** Codex, GPT-6 Sol in ChatGPT Work Mode. **Protocol:** local commit `a4eda26`, mirrored to PR #26 before this base read. **Observation:** Drupal derivative was read around 04:03 UTC by LH023 and the PHP base around 06:35 UTC in this study; exact times in the two read logs. **Overlap:** this intentionally reuses LH023's selected derivative and is one case from the same PHP emergency episode, selected with its declared fixed version already known. **Cost:** model spend unknown; no paid external API.

## Answer

The current published `drupal:10.6-php8.3-fpm` linux/amd64 image's 17 ordered filesystem layers begin with **all 12 layers** of the current `php:8.3-fpm-trixie` linux/amd64 image, matching both the compressed layer digests in their OCI manifests and the uncompressed `rootfs.diff_ids` in their configs. Both configs declare `PHP_VERSION=8.3.36`. This is content-level evidence that the selected derived artifact contains the selected fixed PHP base's filesystem layers, with five additional layers. It does not reconstruct the tag pointer seen by the historical build or prove a running Drupal deployment or the PHP executable's behaviour.

## Method

The [brief](brief.md) fixed the one chosen case, exact base variant, architecture and two prefix tests before the PHP base read. This study retained a Hub tag response, its selected amd64 OCI manifest and config, and a log of four requests including one discarded anonymous bearer. It used one manifest GET and 20,058 retained bytes. [Offline replay](scripts/replay.py) checks each new response hash and OCI digest, rechecks the reused LH023 Hub, manifest and config hashes and digests, and compares both ordered layer lists. It fetches no layer body or executable. The source endpoints and clock boundaries are in [sources](sources.md).

## Limits

- This comparison was made after the derivative had been chosen and after its config declared a fixed PHP version. It is a single selected feasibility case, not a frequency of downstream rebuilds.
- Matching ordered layer digests establishes content identity for those published layer objects. It does not identify the historical mutable tag pointer a builder resolved, prove a unique route to those bytes, validate the executable by running it, or establish that a customer pulled or deployed this image.
- The Drupal image was read about two and a half hours before the current PHP base. If the base tag changed and reverted between reads, that history is not exposed; the comparison is of two retained content-addressed artifacts at their respective observation times.
