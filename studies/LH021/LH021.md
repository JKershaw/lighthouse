# What can public PHP consumer image repositories show of a rebuild?

**Study:** LH021, version 0.1, 21 October 2026. **Status:** first post-release source-feasibility snapshot, no uptake measurement. **Writer:** Codex, GPT-6 Sol in ChatGPT Work Mode. **Protocol:** commit `f58afb6`, before reading selected repositories' current files and runs. **Model spend:** unknown; no paid external API. **Observation:** 21 October 2026, around 17:48–17:51 UTC, exact request times in the [read log](data/snapshot-2026-10-21/read_log.csv). **Overlap:** one PHP release episode already observed in LH018–LH020. This is a small, purposive downstream source check, not independent release evidence.

## Answer

The public records can show selected projects' PHP base-image **instructions** and that workflows **ran at the sampled commit**. In this precommitted three-repository sample, the deterministic four-file cap found three literal `FROM php:` lines for WordPress and four for Drupal; for Nextcloud it selected four unrelated proxy example Dockerfiles. Each repository's ten most recent run records included two successful runs at its sampled head SHA. None of those observations says which base digest a job resolved, whether it pulled layers, whether an image was published or deployed, or whether the patch prompted a change. The Nextcloud result is a coverage failure of this file-selection rule, not evidence that Nextcloud does not use PHP.

The full [summary](data/summary-2026-10-21.csv) keeps the selected paths, run times and exact head SHAs. The cohort was chosen by named public application-image repositories, not by whether they updated for this CVE; it is nevertheless a convenience sample with no wider denominator.

## Method

The [brief](brief.md) fixed three repositories, tree-at-commit reads, a lexicographic cap of four Dockerfile paths and two workflow paths, and ten recent Actions runs each. The collector retained 30 public API responses totalling 673,314 bytes, under the 36-call and 12 MiB ceilings, plus the deterministic [selection manifest](data/snapshot-2026-10-21/selection.json). Every API read returned HTTP 200. The [offline replay](scripts/analyse.py) checks retained byte counts and SHA-256 hashes, verifies each selected blob's Git object SHA, reconstructs the paths from the tree and the literal `FROM php:` classifications, and compares run head SHAs to the sampled commit. The trees were not marked truncated. No logs, derived image manifests, earlier source revisions or publisher analytics were read.

## Limits

- This snapshot was taken after publication, with no frozen pre-event source and image state for the three consumers. A moving base tag in a Dockerfile is an instruction, not the digest actually resolved by a run. A source commit and an Actions run at that SHA are not necessarily a build of the selected Dockerfile.
- The deterministic file cap is deliberately small and misses Nextcloud's application build recipes. A missing literal reference in these four files is unknown for the repository, not an absence of PHP use. Even WordPress's template cannot be interpreted without rendering it.
- The latest-ten runs list is a convenience window. It may omit earlier runs; successful run status alone does not prove a fresh base pull, built artifact, deployment or running patched PHP. No pull or host denominator exists.
- These three public publishers do not represent private CI, PHP deployments or the internet. Counts per file and per run must not be reported as adoption rates.

## Next

Before making an uptake claim, repair the source reader with a bounded rule that selects a repository's *production* template and rendered image recipe, then freeze a pre-event commit and a later commit for the same project. Link a particular CI job to its commit and input digest if the retained log exposes it, and separately read the published derived image digest. This needs a new protocol with missing cases kept. The LH019 moving-tag checkpoints remain the prospective source observation; LH013 remains the standing weekly-baseline question. No consumer adoption article follows from this first feasibility slice.
