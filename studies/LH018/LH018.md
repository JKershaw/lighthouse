# Which public records show the emergency PHP fix moving downstream?

**Study:** LH018, version 0.1, 21 October 2026. **Status:** first bounded snapshot, not a multi-day trend. **Written by:** Codex, GPT-6 Sol in ChatGPT Work Mode. **Protocol snapshot:** commit `d35c517`, before downstream outcome collection. **Observation window:** 21 October 2026, 16:48:44–16:52:42 UTC. **Instruments:** Python 3.12 `urllib` collector and the official vendor, Docker Hub and OCI interfaces in [sources.md](sources.md); [read log](data/snapshot-2026-10-21/read_log.csv), [seven-track summary](data/summary.csv), raw responses and offline [replay](scripts/analyse.py). **Overlap:** the question and source-boundary method of LH006/LH007, but a new security event and ecosystem; no prior Python result is counted again. **Model spend:** unknown in this harness. No paid external API used.

## Answer

At this first snapshot, all three preselected distribution package tracks had vendor records naming a fixed revision for **both** CVE-2026-109618 and CVE-2026-109619. Four preselected version-specific tags of the official PHP image on Docker Hub existed; their linux/amd64 manifests were served, and their configurations declared the corresponding patched PHP source version. The records reach packages offered by distributors and images published to a registry. They do not reveal which organisations installed a package, pulled an image, restarted a worker or ran the fixed PHP binary. A version declaration in an image configuration is a builder's record, not this study's inspection of the binary.

This selected snapshot does not give a patch-adoption rate. Every image tag was chosen because its **name** incorporated a known fixed version; the question there was whether and when the named build appeared, not how much of PHP use it represents.

Those are builder timestamps; the linux/amd64 push and tag push are different events, and none necessarily dates the tag's first-ever publication. Nor can a current record tell whether a notice's `published` field accurately reflects its first public visibility. [The PHP Foundation's account](sources.md) describes an embargoed distributor process, a changed schedule and a premature image release by a provider outside this cohort; that account was known before selection and was not treated as a new independent observation here.

## Method

The [brief](brief.md) fixed the seven tracks before any downstream result was read. The four upstream fixed versions and two CVEs were already known from PHP's advisory. The Debian tracks were chosen to read bookworm and trixie's security paths, Ubuntu noble to read one LTS backport path, and one Docker Hub linux/amd64 tag per supported upstream branch to see where source release becomes a published image. The image variants are deliberately different, so this is not a controlled speed comparison. The event was selected because it was in the news, and these seven tracks are purposive, not random.

The collector retained 26 HTTP observations, including four ephemeral anonymous registry-token requests whose bearer bodies were discarded. Each retained response has an observation timestamp, URL, status, byte count and SHA-256 in the log; the replay verifies hashes and source fields, producing `data/summary.csv`. The first snapshot used fewer than 60 collection calls and less than 50 MiB; no layer or executable was downloaded or run. All seven tracks answered. The source list records exact URLs, publication dates where stated, and what each can show. The collector refuses to overwrite this timestamped snapshot; a later read needs a new run and output directory.

For Debian, two per-CVE tracker pages were parsed for the specified branch and source package, checked against DLA-4848-1 and DSA-6574-1, and the two dated advisories read. For Ubuntu, two official CVE JSON responses were parsed for `php8.3` in noble's security pocket and checked against USN-8948-1. For images, the Docker Hub tag response's linux/amd64 digest was read as one registry manifest; its configuration digest led to the corresponding configuration. The `PHP_VERSION` and `PHP_URL` declarations were checked against the preselected fixed release number. All four configurations also record a build step that fetches the declared source archive; its success or the resulting executable was not independently checked.

## Limits

- Vendor `fixed` and `released` statuses are the vendors' claims. The named security-pocket revision is evidence of a distribution fix path, not evidence of the version held by a machine. A vendor backport could carry a fix while its leading upstream number stayed old, as Ubuntu's `8.3.6-…` revision demonstrates.
- A version-specific Docker tag and a configuration declaration are stronger than a tag name alone, but an image's layers were not inspected. A manifest and config say what was published and declared; they do not prove its bytes execute correctly or that anyone ran them. Current tags are mutable, and anonymous listing cannot reconstruct what a moved tag previously named.
- Debian's date-only advisories cannot be compared to an hour in a release schedule. Ubuntu's recorded notice time is not the time of package installation. Image push times are registry metadata for selected linux/amd64 manifests and tags, not a site-level rollout. Do not combine them into a single “hours to patch” number.
- None of the sources identifies a compromised system or an attacker. The evidence does not estimate PHP's internet-wide exposure, penetration of the fixed versions, whether AI changed patch speed or autonomous propagation.
- A later snapshot of the **same** tags would test whether their current digest moves, if the first digests remain retained; it would still not reveal installations. A cohort of older fixed and moving tags, selected without already knowing their outcomes, is needed to estimate availability patterns rather than merely confirm named new tags.

## Next

A separate time-bounded follow-up can take new snapshots of the same seven tracks and record changed digests, revisions and status corrections, keeping missing readings unknown. To get closer to installed state, inspect a small number of image layers or attestations under a new byte budget and compare with the declared PHP version. To learn about actual rollout, collaborate with willing operators or use a defensible aggregate telemetry source; public registry records alone do not reach it.
