# A Drupal image is published; its base resolution remains unseen

**Study:** LH023, version 0.1, 22 October 2026. **Writer:** Codex, GPT-6 Sol in ChatGPT Work Mode. **Protocol:** local commit `492163d`, before this case's new reads. **Observation:** about 04:02–04:04 UTC, exact UTC request times in [the log](data/snapshot-2026-10-22/read_log.csv). **Overlap:** same emergency patch as LH018–LH022. **Selection:** disclosed post hoc choice of a tag seen in LH022's failed selection, so no independent cohort inference. **Cost:** model spend unknown; no paid API.

## Answer

The known `drupal:10.6-php8.3-fpm` production tag had a published linux/amd64 image at this observation. Its exact manifest and config hashes verified, and the config declares `PHP_VERSION=8.3.36`, the fixed 8.3 source version. The production Dockerfile's literal base instruction is `FROM php:8.3-fpm-trixie`. No selected public source Actions run after the PHP image publication at the frozen heads exposed a resolved PHP base digest, and the config has no ancestry label. This does not prove when or from which base digest the derivative was built, that it was deployed, or that an executable was independently patched.

## Method

The [brief](brief.md) fixed this exploratory selection after LH022's documented failure. Three GitHub content API responses and a Hub tag response, anonymous OCI manifest and config were retained under [the snapshot](data/snapshot-2026-10-22/read_log.csv). One anonymous bearer response was discarded and logged. Seven reads retained 38,690 bytes; all succeeded. [Offline replay](scripts/replay.py) checks response lengths and hashes, all three Git blob SHAs, the selected amd64 OCI manifest and configuration digests, and the declared PHP version. It does not execute a binary or read layers. The matched run list and the manifest stanza used for selection are retained in LH022's snapshot, so this case reuses those observations without counting them as new.

## Limits

The `10.6` tag was selected after seeing its existence in the LH022 manifest. Current image metadata cannot reconstruct earlier tag pointers. The selected platform push time is a Hub metadata claim, not proof of continuous availability or a local build event. The Drupal source Actions runs may be template and lint checks rather than production image publication; the official-images publisher has a separate pipeline. A declared `PHP_VERSION` and a `FROM` line do not expose the resolved base digest, nor prove a running deployment. No adoption denominator exists.
