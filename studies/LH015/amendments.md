# LH015 amendments

All six were made on 29 September 2026, after recipes were seen, by the research agent that ran phases 2 and 3 (the brief's "writer", by the driving session's addition 2). The brief's stopping condition allows this: "A case these rules do not decide is judged by the question's own test (does a build from the recipe take L's version from a timed file?) and recorded as a dated amendment naming the builds it affects". The affected builds are listed by build in data/judgements.csv (column `amendment`), and for amendment 5 in data/recipes.csv (column `note`). No amendment changes the question, frame, classes, pair rule, measures, conventions or seed.

1. **A manifest that reads a T file.** When a step installs the project (`pip install .`, `-e`, a path, or `uv pip install` of it) and the project's manifest takes its dependencies from a T requirements file at build time (`[tool.setuptools.dynamic] dependencies = {file = [...]}` in pyproject.toml, or setup.py reading the file into `install_requires`), and that T file is in the build beside the manifest, the step takes L's version from the T file: class 1. The brief's list of ways to take L from T names only a manifest that is itself in T. 95 builds, 48 of them at snapshots, in 11 repositories: aesuli/push_service, aider-ai/aider, bmosoluciones/coati-payroll, chenglinpoly/multi-level-agent, esphome/esphome, jahlives/openssl_encrypt, mindsdb/mindsdb, netflix/lemur, nucypher/nucypher, toluaina/pgsync, tvick64889/forgepair.
2. **A pin in a file whose name LH008 did not read.** A build that installs from a file not in T which pins L exactly by LH008's content rule, but whose name LH008's rule does not read (`requirements.lock`), takes a pin whose moves were not timed: class 4. 2 builds, both at heads: bmosoluciones/now-lms.
3. **Files checked out from the repository's own `.git`.** When a recipe copies the repository's `.git` directory from the context and checks out `uv.lock` from it in the build, that file counts as available to the step: `uv sync --frozen` from it is class 1. 6 builds, 3 at snapshots: iterorganization/imas-mcp.
4. **L named inline with one exact version.** A step that names L with one exact version in the recipe itself, after the other installs, sets a pin whose moves were not timed: class 4, not class 2's "inline", which the brief defines for a range. 2 builds, 1 at a snapshot: supervisely/supervisely.
5. **A recipe that is a symbolic link.** A primary recipe file stored as a symbolic link is read at its target, as Docker's command line resolves a Dockerfile path before the build. 28 builds, 14 at snapshots: cloud-custodian/cloud-custodian, osism/python-osism.
6. **The project's own source fetched from outside the repository.** A build that installs the project's own source fetched at build time (a GitHub archive at `$VERSION`, or `git+https` of the repository) takes L from that fetch, not from the snapshot's files: class 6, external. 7 builds, 4 at snapshots: netflix/lemur (6) and toluaina/pgsync (1). classify.py applies the same reading to a requirements file copied in a RUN from outside the repository (a clone of the project at a release): 16 builds, 8 at snapshots, all chaoss/grimoirelab.
