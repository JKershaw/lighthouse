## What each source is, and its limits, as far as the brief relies on it

- **K1, ClickPy.** A copy, not the original. The tables the brief reads are materialised views of `pypi.pypi` (data/clickpy_schema.csv): `pypi_downloads_per_day_by_version`, `..._by_python` (python_minor), `..._by_system`, `..._by_installer_by_type`; `pypi.pypi` carries `ci`, `libc` (lib, version), `type` and `filename` besides. The staging table `pypi_raw` holds `python` as a full string and `distro.libc`; the step from it to `pypi.pypi` is not in the catalogue. ClickPy's own README (D05) documents a backfill import that sets `python_minor` to the first two dot-separated parts of `python` and `system` to `system.name`, and keeps only rows where both are non-empty; whether the live ingestion does the same was not checked.
- **K2, PyPI JSON.** The versions and files listed at the read; a deleted version is absent, `yanked` is the state at the read, and a file's `requires_python` is the metadata the installer reads. Declared requirements (`requires_dist`) are the version's own metadata; for a version read through the project JSON they are the latest version's.
- **K3, the installers' source.** pip 26.2.1 (`src/pip/_internal/network/session.py`, `user_agent()`): `python` is `platform.python_version()`; on Linux, `distro.libc` is `{"lib": "glibc", "version": ...}` when a glibc version is found and absent otherwise (`utils/glibc.py`, `libc_ver()`), so pip never reports musl; `system.name` is `platform.system()`. uv 0.12.8 (`crates/uv-client/src/linehaul.rs`): `python` is the full Python version of the PEP 508 marker environment passed to it, or null when none is; `libc` is glibc or musl with its version, from the platform; `system.name` is the markers' `platform_system`. Which interpreter's markers each uv command passes was not read.
- **D03, linehaul's parser.** pip 6 and later and uv send a JSON user agent that linehaul parses whole; older clients' user agents are parsed by pattern and many carry no Python version.
- **L01, L02.** SPEC 0 recommends dropping support for Python versions three years after their initial release and for core package dependencies two years after theirs; NEP 29 recommended supporting the Python minors released in the prior 42 months. Policies, context only.
- **L03, L04, L05.** Measure declared constraints (L03, L04) or the Python field of pip downloads across all packages (L05); none measures which versions of a library are fetched.
- **Not read.** BigQuery itself (S20); linehaul's BigQuery schema (D04 returned 404); ClickPy's live ingestion; github.com's pages for aiobotocore's issues on its botocore bound (programme.md, Next), which returned HTTP 403 to the previous check and were not tried again.
