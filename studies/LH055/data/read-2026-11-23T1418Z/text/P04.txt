# ARTEX: Agentic Asbestos
ARTEX [131], Research [132], Threat Intelligence [133]

## Executive summary
- ARTEX is an open-source, LLM-driven autonomous penetration testing framework released in July 2026. In October, two threat intelligence companies attributed its use as part of threat actor operations; CrowdStrike linked it to a campaign against South Korean financial institutions, and Microsoft linked it to Storm-0940’s compromise of ConnectWise customer tenants.
- As of November 4, 2026, Censys observed 1,465 hosts running an exposed ARTEX console. About 650 sit in two blocks of identically configured hosting, which leaves roughly 815 distinct-looking deployments. The ARTEX console does not require public-facing access, and overall global deployment is likely higher.
- 155 ARTEX hosts (10.6%) also run at least one other threat that Censys detects. These include other AI attack frameworks, recon platforms, tunneling tools, and C2: Vshell, Cobalt Strike, and Adaptix C2.
- Censys saw open directories on the ARTEX server named in CrowdStrike’s report starting August 18, 2026, seven weeks before that report was published. The directories exposed exploit binaries and a .claude folder.
- That mistake is common: 32 open directories run on other ARTEX hosts today, exposing post-exploitation kits, stagers, and implants.
## What is ARTEX?
ARTEX was published on GitHub as Autumn-27/ARTEX on July 26, 2026, under the AGPL-3.0 license. Its developer, Autumn-27 [141], is also the author of ScopeSentry, a widely used Chinese asset-discovery and vulnerability-scanning platform with more than 2,000 GitHub stars. ARTEX is best understood as an AI agent layer on top of that recon foundation. It syncs assets found by ScopeSentry’s domains, subdomains, IPs, ports, and endpoints straight into its own asset graph.
Figure 1: Web UI of ARTEX
Following public release, the project grew quickly, reaching an estimated 1,500-2,000 stars within ten weeks of release. On October 8, the day after CrowdStrike released a report detailing observed malicious usage, the author (Autumn-27) posted a statement on their GitHub profile, claiming they were not involved in the attacks and that ARTEX was meant for testing within authorized asset scopes. Autumn-27 then stated that the project would go closed-source with no further releases. The repository has since been taken down, but archived copies, translations, and rebrands such as ScopeWeaver are still circulating.
ARTEX is written in Go and uses a Next.js web console, backed by PostgreSQL. ARTEX usage starts with users defining Tasks, which outline the scope, test accounts and goal for agents – the example shown by default is “What to achieve, e.g., gain admin panel access or server privileges”. Running tasks leverages multiple sub-agents for completing the goal.
A Planner agent turns the goal into attack “intents”. Worker agents claim those intents, run tools (e.g., nmap, which ships in the Docker image), and write results back. An event-driven engine repeats that explore-decide-execute loop until the goal is met. ARTEX tracks two graphs: an asset graph of what the target looks like, and an exploration graph of how much of it has been tested. It also includes mitmproxy [142] for traffic recording, and it works with Anthropic, OpenAI, or any OpenAI-compatible model endpoint. Microsoft describes [143] it as able to run “from reconnaissance through data exfiltration” with minimal human input.

## ARTEX in two campaigns
Not every ARTEX instance is operated with malicious intent, and some of the hosts publicly exposed are likely operated by authorized testers. As with all offensive security tools, there exists the potential for malicious usage. Two notable reports were released in October 2026 that provided context into observed malicious usage.
### South Korean finance (CrowdStrike, October 7)
On 7 October 2026, CrowdStrike reported [144] that an unattributed actor using ARTEX targeted a South Korean finance company from late September to early October. The actor was assessed with moderate confidence to be a financially motivated Chinese speaker. The actor breached a broker-facing loan inquiry service at one bank and an employee mobile system at another, and exfiltrated data. ARTEX ran on [ipv4 withheld] with DeepSeek v4.1-flash as its main model, which the actor likely bought through an API reseller. The actor also ran Claude Code sessions backed by GLM and Grok. CrowdStrike found the activity because the actor left open directories exposing a .claude folder, prompts, session histories, and ARTEX configuration files.
CrowdStrike’s report identified an open directory exposed at [ipv4 withheld]:18899. Censys scan history for that host shows how long it had been exposed:
Figure 3: Service history for [ipv4 withheld]
The file names show the actor working on targets well beyond South Korean banks, including payment and gaming services. That fits CrowdStrike’s observation of broader activity tied to the same persona.
The more useful finding for defenders is that this mistake is not unusual. During the writing of this report, Censys observed 32 open directories on ARTEX hosts. Examples:

### Storm-0940 and ConnectWise (Microsoft, October 21)
Microsoft attributed [145] the ConnectWise Cloud Backup supply-chain compromise to Storm-0940, a China state-aligned actor active since 2021. The group used ARTEX to automate scanning, password spraying, and OAuth application abuse. It attempted sign-ins to more than 2,250 tenants, peaking at 2,900 attempts per minute, and some victims saw privileged cloud access in under three hours. Microsoft also notes it has seen multiple actors across regions using ARTEX.
## Censys ARC Perspective
Censys detects ARTEX consoles by their page title (localized versions start with “ARTEX” followed by a space, colon, or dash) together with Next.js static assets. Censys Platform users can see them under the threat label ARTEX for hosts and web properties.
(web.endpoints.http.html_title=~"^ARTEX[ :—]" and web.endpoints.http.body: "_next/static" ) or (host.services.endpoints.http.html_title =~ "^ARTEX[ :—]" and host.services.endpoints.http.body: "_next/static")
As of November 3, 2026, this matches 1,465 hosts.

Two hosting netblocks account for about 44% of hosts and merit further analysis:
- PEG Tech (AS54600): 493 hosts. They share one of two identical port layouts across 13 /24 networks. 125 hosts each sit in [ipv4 withheld] and [ipv4 withheld].
- Yancy Limited (AS138415): 157 hosts. They share an identical CyberPanel-plus-mail-server template, mostly in [ipv4 withheld].
Uniform configurations like these suggest a provisioning template rather than hundreds of individual operators. Excluding them leaves about 815 ARTEX deployments. Yancy Limited and Zenixcloud (22 ARTEX hosts) also hosted proxy IPs listed in CrowdStrike’s report.
Yancy Limited (AS138415) has come up in Censys reporting before. In December 2025, we observed a surge of Cobalt Strike listeners, mostly on Yancy, that peaked at 407 new hosts in a day and dropped to zero within two weeks. We assessed them as likely “a couple of unique instances spread across hundreds of IP aliases.” The Yancy ARTEX hosts follow the same pattern: one server template repeated across many addresses. The full details connection between the two remains unclear, but in both cases a large host count likely comes down to a few real servers.
We also see customized builds: ARTEX MX on four adjacent hosts at [ipv4 withheld] – [ipv4 withheld], plus ARTEX v2 · Agent Security Workbench and a handful of other renamed consoles.
### What else runs on ARTEX hosts
Of the 1,465 ARTEX hosts, 155 (10.6%) carry at least one other Censys threat detection.
Figure 4: Threats identified running on the same hosts as ARTEX
Three patterns stand out.
Operators stack AI attack frameworks. The most common companion to ARTEX is another AI pentesting tool. CyberStrikeAI shares hosts with ARTEX on 70 hosts, and PentAGI, HexStrike AI, and RedAmon also appear. Operators appear to be using multiple agent frameworks side by side.
AI tooling sits next to conventional C2. A small but clear set of hosts pairs ARTEX with established command-and-control and tunneling tools:
- [ipv4 withheld]: ARTEX and PentAGI, alongside a Cobalt Strike teamserver on port 50050 and an Adaptix C2 listener on 4321.
- [ipv4 withheld]: two ARTEX consoles, Vshell, NPS, Gophish, a mail server admin panel, and a page titled “SuperAgent 主监督” (“SuperAgent main supervisor”).
- [ipv4 withheld]: an ARTEX console on 443 and a Vshell login on 18080
- [ipv4 withheld]: ARTEX with two Vshell listeners and an FRP server.
- [ipv4 withheld], [ipv4 withheld], [ipv4 withheld], [ipv4 withheld], [ipv4 withheld]: five identically configured hosts, each running ARTEX, CyberStrikeAI, ARL(Asset Reconnaissance Lighthouse), and Vshell. Likely this is either a device with multiple public IPs on the same subnet or a cloned image.
LLM access is part of the tech stack. 43 ARTEX hosts also run self-hosted LLM gateway or reseller software, mainly CLIProxyAPI (19) and New API (18). The actor in CrowdStrike’s report bought DeepSeek access through a reseller. For defenders, unfamiliar LLM proxies and resellers in egress logs are worth investigating.
### Hunting ARTEX with Censys
- Console: the query above, or the ARTEX / ScopeWeaver threat labels in the Censys Platform.
- Default port: 8787/tcp, with 8790 and 443 common.
- Pivots: look for co-located open directories, Vshell or FRP listeners, and LLM proxy software (CLIProxyAPI, New API) on the same host.
- History: check scan history for mitmproxy banners and short-lived Python SimpleHTTP servers on high ports. They often appear before the console does.
