## Answer

The preselected exact `11.3-php8.3-fpm` tag was absent from the current official-images `library/drupal` manifest. Under the fixed rule there is no selected derivative, so this case cannot link a production recipe, base digest or image artifact. The study stops at selection. It does not classify Drupal's uptake.

## Findings

The manifest does contain other `php8.3-fpm` tags, including a `10.6-php8.3-fpm` stanza whose `GitCommit` and `Directory` are retained in the raw response. That was noticed after the selection failed and is not substituted here. The 20 most recent Actions runs returned in the same bounded read have no head equal to either the selected pre-event commit or current head after the PHP image time under this study's exact filter. An Actions listing alone would not establish a production image build.

## Method

The [brief](brief.md) fixed the repository, exact tag test, clocks and bounds before collection. [The selection record](data/snapshot-2026-10-22/selection.json) and five raw API responses retain the manifest, pre-event commit query, current head and recent runs. Their URLs, byte counts, SHA-256 hashes and statuses are in the log. All five returned HTTP 200; no registry read or job log was made because the derivative selection failed. The script refuses overwrite. The selected tag's absence can be replayed by decoding the retained manifest's base64 content and checking exact comma-separated Tags values.

## Limits

This is a failed exact-tag rule, not evidence that the repository lacks an 8.3 image. A separate explicitly post-selection case can choose a tag known to exist and measure how far the public chain reaches; it cannot turn this failure into a successful preselected case. No prior derived-image digest exists in this study.
