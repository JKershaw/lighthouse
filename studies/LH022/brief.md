## Question and selection

Can the public production recipe, a particular build run, its resolved PHP base digest and a published Drupal derivative be linked across the patch event? Use `docker-library/drupal` and the `library/drupal` entry in `docker-library/official-images`. Choose the first manifest stanza, in file order at the observation, whose Tags field contains an exact `11.3-php8.3-fpm` tag; if absent, record no selected derivative and stop that path. The stanza's GitRepo, GitCommit and Directory choose the production Dockerfile, not an alphabetic repository sample. Freeze the upstream repository's latest commit before 21 October 00:00 UTC and its default branch head at the read; read the selected recipe at both commits when the path exists. Do not substitute a different tag or project after seeing a result.

For workflow linkage, inspect at most 20 public Actions runs of `docker-library/drupal` around 21–22 October, and at most two plausible jobs' public logs, preferring a run whose head equals a frozen source commit and whose time follows the 21 October PHP image publication. Record missing logs or absent matching runs as unknown. If a log explicitly records a base-image digest, compare it to the same PHP variant digest; a successful job without that line is not a resolved-base observation. Inspect the chosen derived tag's current Docker Hub index, amd64 manifest and config at most once; if present, retain digest, declared ancestry if any, and timestamp. A current derivative is left-censored with respect to when it changed absent earlier retained registry state.

## Comparison and limits

Compare the two immutable source commits for instructions and the run's exact head for execution. A source `FROM php:8.3-fpm` is an instruction whose resolution depends on build time and cache; a derivative image digest is an artifact, not evidence of deployment. No project or machine denominator exists. Keep source publication, base resolution, derived publication and deployment distinct. A failure to expose a job or digest is unknown for that boundary, not negative uptake. Classify the deployment issue's reports as self-reported, not an exhaustive outage interval.

At most 40 GitHub API reads, six Docker Hub or OCI reads, 12 MiB retained response bodies, and two CI log reads. No image layers, builds, executable runs, secrets or private data. Stop on rate limit or ceiling, retain full bounded response bodies, retrieval times, statuses and hashes, and provide offline replay of the measured fields. The stopping condition is one attempted reading at each boundary, including missingness. This case cannot estimate overall adoption or the effect of the advisory.
