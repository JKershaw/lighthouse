# Which public records connect PHP's security notice to its official image publication?

**Study:** LH020, version 0.1, 21 October 2026. **Status:** one selected retrospective publisher-chain case. **Written by:** Codex, GPT-6 Sol in ChatGPT Work Mode. **Protocol:** commit `6fc2af8`, before API collection. **API observation:** 21 October 2026, 17:42–17:45 UTC; exact times per response in [the read log](data/snapshot-2026-10-21/read_log.csv). **Model spend:** unknown in this harness; no paid external API. **Overlap:** the PHP release and four registry observations are LH018 and LH019 evidence reused here, not independent new releases.

## Answer

The public record gives a dated path from an early issue in the PHP image-maintainer repository, through two explicitly linked pull requests, their reviews and CI, to images later observed on Docker Hub. It is more than a list of advisories: the second PR names the first, and the official-images test rerun reports 68 successful jobs. It is less than a complete build or adoption history: LH020 did not inspect Docker's intermediate `meta` and staging records, and neither a CI success nor a registry image says anyone installed or ran it. A public issue at 07:17 UTC documents communication in **one selected venue**, not the first notice to any maintainer or a count of readers.

These are distinct clocks. The source PR was open for 34 minutes 25 seconds. The official-images PR opened 10 minutes 20 seconds after the source PR merged and remained open for 47 minutes 2 seconds. The earliest selected platform's Hub push field is about 70 minutes after the official-images merge, and the first LH018 tag observation is about 92 minutes after it. Those are descriptive intervals between public source fields, not causal build durations or a measure from the PHP project's **date-only** advisory. Full source precision and all 34 extracted rows are in [the event table](data/events-2026-10-21.csv).

## Method

The [brief](brief.md) fixed one retrospective chain and the exact issue, two PRs, API paths and known official-images run before reading API outcomes. A collector retained 15 public unauthenticated responses, 790,484 bytes in all, under the 24-request and 8 MiB ceilings. Each [raw response](data/snapshot-2026-10-21/) has a retrieval time, URL, status, byte count and SHA-256. The [offline replay](scripts/analyse.py) verifies hashes; checks the PR head SHAs against their commit lists, check records and the selected official run; confirms merge events and job counts; and reconstructs the event table. Every requested endpoint returned HTTP 200. The first lexicographic PHP run ID exposed by the selected-head checks was #39610715340, an ancillary one-job check. Its success does not stand in for the other PHP CI runs; the 68 selected-head check records are separately retained. The official-images run was fixed in the protocol and its retained 68 jobs include named PHP image test jobs. CI logs were not fetched.

## Limits

- These source and release PRs were known before the protocol. This is a retrospective selected case. Their explicit references show documented linkage, not who learned from whom, why they acted or how far the information spread outside these repositories. The 07:17 issue is not asserted to be the earliest public mention.
- The PHP advisory has day precision. A planned disclosure hour is not substituted for a verified release instant. Source commit author times, PR times, CI times, Hub platform pushes, tag pushes and Lighthouse observations answer different questions.
- The selected official-images CI run is a successful test rerun. The API returns 71 selected-head check records, some outside that run. Logs, artifact contents and Docker's subsequent `meta`, staging and per-architecture publication records were not read. The gap from manifest PR merge to registry is observed at its endpoints, not explained internally.
- The matched image variants are different across PHP branches. A Hub metadata push time is a source field, not independently verified first public availability. Version declarations and manifest identities do not inspect a binary. No measure here reaches pull share, installed hosts or running deployments.
- Public GitHub and Docker records exclude private coordination, private CI and unobserved consumers. Comments and check counts are not a denominator for uptake, and these two CVEs are one release episode.
