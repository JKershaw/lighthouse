3. Aggregate figures only. **Evidence too thin, and what the proposals overstate.**

- P-0012. The title says GitHub "switches off" the trigger; GitHub says it blocks it by default and lets a policy allow it, and those policy choices are dark, so what public data can show is mainly runs that fail and workflows that change. "The door a self-spreading worm used": StepSecurity's report that the TanStack worm entered this way appears in scout 3's lead text but not in its quotation of the page, and the other cases scout 3 reports entered by other routes (ChainDrop through a maintainer's GitHub account, LiteLLM through stolen GitHub CLI OAuth tokens, MemTensor through commits that made release pipelines hand over tokens). Scout 3's "the counterfactual is lost once workflows are rewritten" does not hold: the rule has run in evaluate mode since before the original 2 November date, so the state before owners were warned is already past and readable only from history, as it will be after 9 November. If the keeper wants it, a brief fixed before 16 November can draw its sample from repositories Lighthouse already holds and read the 9 November window afterwards; I did not check today how long GitHub keeps run records for public repositories.
- P-0013. "Urgent" does not meet the plan's test (above). "The charter's degradation in its plainest form, already happening" reads as Lighthouse's own claim of harm; kernel.org's post, as scout 7 quotes it, speaks of scrapers, not of AI as such, and calling the load AI activity's cost is an interpretation, to be kept as reported by the operators. The panel would add Lighthouse's own automated requests to operators who report being overwhelmed and blocking even friendly checkers (COAR): it needs its presence labelled, an identifying User-Agent, robots.txt respected and an end date. Access is unproven: Wikimedia answered 429 and the Wayback Machine's index reset the connection from this container (scout 7). Anthropic also runs crawlers, so any attribution of load to AI crawlers needs the model disclosure.
- P-0014. The proposal is worded with care, but this file's heading "Signs of self-sustaining spread" overstates what was read: lab evaluations and simulations (capability in controlled settings), a malware lineage that spreads through stolen tokens but is run by people as reported, counts of exposed services (exposure, not spread), and AISI's account of unsanctioned actions, which says it has "not identified any resulting real-world harm". None is reported as AI activity sustaining itself outside a lab. The next sweep might retitle the theme "Reports that bear on self-sustaining spread".
- P-0016. The finding is credited to researchers "doing security testing for OpenAI's Codex Security" (CSO, via scout 2); whether a model found the flaw is not established. OpenAI competes with the company whose models Lighthouse runs on, so the model disclosure applies, and reviews should look for wording harder on OpenAI than the sources allow. Taking Brotli as a second case for "When a model finds the bug" would widen an investigation whose page says it does not follow every AI-related security story: the keeper's call. "Fixed upstream in February without a release" is The Register's claim, to be read in the upstream history.
- None of the five proposes contacting anyone outside the repository.
