## Draft notice (for near the opening, above the 30 October notice)

> **Later evidence, [date set at release].** On 19 November PHP released versions 8.5.13, 8.4.28, 8.3.37 and 8.2.36, and its news page calls each "a security release". Those entries don't name the further flaw, CVE-2026-115560, and the "full advisory" PHP promised on 23 October "with the next release" wasn't on its news page when we last read it, on 23 November. The flaw's public record, which PHP published that afternoon in its role as the body that numbers PHP's flaws, says it "affects PHP versions before 8.2.36, 8.3.* before 8.3.37, 8.4.* before 8.4.28 and 8.5.* before 8.5.13". By 23 November, Debian, Red Hat and SUSE listed packages built on the new versions as fixed, which is their own claim and one we haven't tested; Ubuntu listed every package as still awaiting triage, and Google's open source vulnerability database (OSV) had no entry. Over the month before, among the fifteen security bodies and vulnerability databases we watched, only CERT-EU, the EU institutions' security team, passed on PHP's advice to switch the feature off, and the databases had no entries while that advice was current, apart from SUSE's, which didn't carry it. Cloudflare's page still said, on 23 November, that the flaw "will be fixed in PHP's next regular release". [What changed after 22 October](#what-changed-after-22-october).

Checks behind each sentence (for the reviewers, not for the piece):

- "That afternoon": the CVE record's `datePublished` is 2026-11-19T14:42:48.511Z, assigner `php` (`cve_org_0.raw`, 23 November). The quoted range is from the description in the CNA container, whose own `providerMetadata.dateUpdated` is 2026-11-19T19:36:33.887Z, so the range text read on 23 November may postdate the first publication. If the chain wants to avoid that nuance, drop "that afternoon" and say "that day".
- Trackers: `debian_0.raw` (bookworm (security) 8.2.36-1~deb12u1 and trixie (security) 8.4.28-1~deb13u1 fixed), `redhat_0.raw` (nine `affected_release` rows, with `package_state` still "Affected" for some RHEL 9 and 10 streams), `suse_0.raw` (overall state "Pending", with package versions including php8 >= 8.2.36, 8.3.37 and 8.5.13, and one php8 8.0.30 build, whose relation to the 19 November releases the page does not state), `ubuntu_0.raw` (every listed package needs-triage), `osv_0.raw` (HTTP 404, "Vulnerability not found"), all 23 November.
