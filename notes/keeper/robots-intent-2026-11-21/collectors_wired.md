# Collectors wired to `lh_fetch.save_body`, 21 November 2026

**In short.** Since the second sweep (end of this note), every script in the repository that fetches over the network and keeps a body does so only through `lh_fetch.save_body`, live or not, and `python3 -I scripts/lh_fetch.py --selftest` tests the gate and the keep path offline. The keeper decided on 21 November 2026 that Lighthouse keeps no page body where a site's robots.txt refuses `*`, an AI-training crawler or an archiving crawler, or where the page reserves itself (noai, TDM). This note lists every collector a scheduled read will run, and what it now does: each writes a fetched page body only through `scripts/lh_fetch.py`'s `save_body`, and where that refuses, writes no body and logs `body_kept = "no: <reason>"` (a column, a JSON field or the log's note, as each log allows), plus a derived file (`write_derived`) or this run's git-ignored copy where the study's measures need facts from the page. The rule itself is applied in one place, `lh_fetch.keep_decision`, which `save_body` uses. Nothing that is kept changed name or place; nothing fetched changed.

Written by a subagent of the Watch run of 21 November 2026 (Claude Code, Claude Opus 5.5). Which live hosts refuse keeping today was read through the gate, one robots.txt per host: [live_hosts_survey.py](live_hosts_survey.py), output [live_hosts_survey_output.json](live_hosts_survey_output.json) (287 hosts' robots.txt read; a URL "not fetched" there is refused fetching altogether under the recurring rule, so it never reaches `save_body`).

## Every fetching script: the second sweep (21 November 2026)

Written by a subagent of the same Watch run (Claude Code, Claude Opus 5.5), at the keeper's request for one code path with nothing left over: the dormant scripts the first sweep left alone, and every other script in studies/, notes/ and essays/ found to fetch over the network and write a response body. Nothing was run against the network: every check below stubbed it (urllib's `OpenerDirector.open`, requests' `HTTPAdapter.send` and the curl subprocess intercepted, robots.txt answering allow-all, GPTBot refused with `LIGHTHOUSE_PROVIDER=anthropic`, ia_archiver refused, or allow-all with a page carrying `<meta name="robots" content="noai">`).

The pattern, as for the live collectors: fetch through `lh_fetch`'s gate; save a body only through `save_body` (which applies `keep_decision` and withholds email addresses); where it says no, write nothing and log `body_kept` "no: <reason>" in whatever slot the log has (a JSON field, a CSV column added only when some body was not kept, the `error` or note column), and `write_derived` where a later step needs facts from the page. A kept body keeps its name and place, and where a script's log has fixed columns a kept read's log is unchanged. Most of these scripts are one-off records of past reads (their docstrings now say so) and will not run again; for them the kept-body behaviour is identical except where noted (email withholding, which AGENTS.md has required since 8 November, and one gzip header).
